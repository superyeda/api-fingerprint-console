01

Bark：服务器与设备 Key 是两回事

适合接收通知的 iPhone / iPad

  1. 在 iPhone / iPad 安装并打开 Bark

    从 App Store 官方应用 ↗ 安装，允许发送通知。参阅 Bark 官方文档 ↗ / 官方开源项目 ↗。不要把设备 Key 发给他人。

  2. 在 App 首页找到推送示例并复制设备 Key

    示例通常包含服务器 + 设备 Key + 消息。以下所有值都是占位示例，不是真实凭据：

    https://api.day.app/YOUR_DEVICE_KEY/测试消息

    设备 Key 不是模型 API Key（例如 mqs / zkj 接口凭据），二者不能互换。其中 https://api.day.app 是服务器；YOUR_DEVICE_KEY 才是发给这台设备的 Key；/测试消息 不是 Key。若 App 只提供完整链接，请在本机自行取出两个斜线之间的 Key 段，不要把整条链接粘贴到服务器输入框。自托管服务使用自己的源地址。

  3. 在控制台分开填写

    选择 Bark。服务器填 https://api.day.app（仅源地址，无路径、Key、查询串或账号密码）；密码式「设备 Key」框只填 YOUR_DEVICE_KEY 对应的真实值。分组示例 API 指纹巡检；提示音可留空。本程序 POST 到服务器的 /push，把设备 Key 放在 JSON 中，不会把真实 Key 拼成展示链接。

  4. 保存，然后明确确认测试

    点击「保存通知配置」，再点「发送测试通知…」。确认框始终测试已保存通道，未保存草稿不会生效；即使检测通知开关关闭，也可明确授权单次测试。保存不会发送，测试不调用模型。每 30 秒最多一次，待处理时禁止重复提交；HTTP 最长等待 10 秒，不重试、不跟随重定向。

Windows 电脑可以向 iOS Bark 发送

发送端是电脑，接收端是你的 iPhone / iPad，与电脑是不是 Mac 无关。这里不宣称 Android 支持 Bark 官方 iOS 客户端；Android 请用你自己的兼容推送服务 / Webhook 接收方案，并按接收端格式配置。

02

Webhook：先选接收方，再选消息格式

通用 JSON / Slack / 企业微信 / 钉钉

  1. 在接收服务创建入站 Webhook / 群机器人

    从服务官方管理界面取得完整 URL；不要填聊天网页地址。示例：https://hooks.example.com/services/YOUR_WEBHOOK_TOKEN。企业微信占位示例：https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_WEBHOOK_KEY。完整 URL 常含凭据，按秘密保护，只放在密码式 URL 输入框。

  2. 选择匹配的固定消息体格式

    程序 POST JSON；YOUR_TITLE / YOUR_BODY 为下方示意占位内容。接收端需支持对应格式。可选 token 会放入 Authorization: Bearer YOUR_BEARER_TOKEN 请求头，只填写 token 值，不要重复 Bearer。企业微信 / 钉钉等机器人若要求签名、时间戳或特殊消息结构，本程序未提供额外签名配置；签名 / 时间戳过期需由你自己的适配服务处理。请使用自有兼容中转，不要尝试拼接命令，也不保证任意第三方平台即填即用。

通用 JSON / Slack 消息体

通用 JSON 用于你自己的接收端：

{"event":"api_fingerprint","title":"YOUR_TITLE","body":"YOUR_BODY","text":"YOUR_TITLE\nYOUR_BODY"}

Slack Incoming Webhook：

{"text":"YOUR_TITLE\nYOUR_BODY"}

Slack 官方 Webhook 文档 ↗

企业微信 / 钉钉消息体

企业微信群机器人：

{"msgtype":"text","text":{"content":"YOUR_TITLE\nYOUR_BODY"}}

钉钉群机器人：

{"msgtype":"text","text":{"content":"YOUR_TITLE\nYOUR_BODY"}}

两者文本结构相似，但地址、机器人安全策略与响应语义不同，仍应选择相应格式。检查接收端要求的关键词或白名单，不要关闭组织安全限制来绕过校验。

填写后独立保存，再确认真实测试；不要用付费「手动检测」来验证推送。URL/token 留空保持旧值，勾选清除后保存需二次确认。

03

没有收到？按结果逐项检查

最近测试与最近检测通知各自留档，不互相覆盖

未配置 / 通道不可用 / 通知关闭

「配置可用」仅指已存所需凭据且平台具备通道能力，不是网络验证。检查选中的已保存通道与凭据状态，保存后测试。旧本机命令仅支持 macOS；Windows 请改选 Bark / Webhook。「检测通知关闭」只影响检测摘要，不禁止明确确认的测试。

401 / 403：认证或权限

远端拒绝时，核对设备 Key / 完整 Webhook URL / Bearer token 是否过期、复制有误或对应其他服务器；确认机器人权限、访问白名单与服务配额。重新录入并保存后再测。若是本机安全会话失效，刷新控制台后重新确认；不要把密钥或完整地址粘贴到截图、日志或求助消息中。

网络 / TLS / timeout（超时）

确认电脑能访问服务器、DNS / 代理 / 防火墙正常。TLS 失败应修复证书、系统时间或可信证书链；程序不跳过证书验证。不应为了绕过 TLS 而开启 HTTP。请求最多等待 10 秒，超时表示未能确认结果，并不证明远端一定没收到；先查看手机和接收端，至少等 30 秒再手动决定是否重测。程序不自动重试。

远端拒绝 / 其他 HTTP 状态 / 重定向

检查所选格式是否与 URL 对应，以及机器人关键词、白名单、服务配额或限流规则。程序不跟随重定向：应使用官方提供的最终 HTTPS 接收地址，不要通过短链接。页面仅显示安全结果与状态码，不展示远端原始响应、真实 URL 或凭据。修正保存后再测试。

accepted / 服务已接受，但手机不显示

这只说明服务接受提交，不保证最终送达或弹窗。检查手机设置里的 Bark 通知权限、横幅 / 声音、专注模式 / 勿扰、网络连接、App 内服务器与设备 Key 是否匹配，以及是否被分组折叠。Webhook 接收方还可能异步处理；查看自己的接收端状态。不要把「服务已接受」理解为手机已显示，也不要连续重测。

409 处理中 / 429 过于频繁

一次只允许一个测试；测试按钮在提交与 30 秒冷却期间禁用。其他页面 / 窗口也共享服务端限流。409 时等待现有测试结束，429 时等待至少 30 秒。不会自动重发；结果未知时先检查接收端，避免重复消息。

04

隐私、迁移与平台边界

凭据不回显，所有示例都只是占位值

版本更新后，先确认系统定时任务也已升级
  1. 识别旧运行版本提示

    如果页面显示「系统定时任务仍在使用旧版本」，说明新界面已打开，但系统任务仍指向旧的不可变运行目录。更新软件不会擅自改写已有任务；不要以为旧 worker 已能使用新的 Bark / Webhook 配置。

  2. 主动选择「应用新版本到系统定时」

    此按钮与平常的启用 / 停用不同。阅读并确认后，才会更新本应用系统任务，复用服务器里已保存的检测间隔和执行分钟，不使用尚未保存的调度草稿。若检测到外部旧监控，还必须勾选确认已检查并暂停，软件不会替你修改它们。更新不会立即检测或调用模型；若任务当前停用，确认中会明确提示应用后将启用。

  3. 确认状态，再保存通知

    旧版本系统任务仍启用时，通知配置保存会被阻止；也可以先自行确认停用本应用旧系统任务，再保存。升级成功、旧版本提示消失后，独立保存通知配置，然后另行确认真实测试。通知测试和本教程始终可用，但测试成功不能证明旧定时任务已升级；仍需检查系统任务状态。

  • 输入不是查看：设备 Key、完整 Webhook URL、token 只允许录入、不预填，不写 localStorage。留空保持已保存值；替换需输入新值。勾选「清除」后保存会再次确认，清除不是暂时关闭通知。
  • 导出 / 导入：仅导出接口、别名与非秘密通知偏好，不包含 API Key、Bark Key、Webhook URL、token 或凭据存在标记；导出中的检测通知始终关闭。整份导入会替换配置、清除通知凭据并保持关闭；API Key 条目也会换新 ID、无凭据且停用。迁移后重新录入、保存，再明确测试。
  • 存储差异：macOS 数据通常位于 ~/Library/Application Support/API Fingerprint Console/data，使用本机文件权限保护；Windows 通常位于 %LOCALAPPDATA%/API Fingerprint Console/data，通知凭据使用当前账户 Windows DPAPI。以设置页返回的平台与保护信息为准。不要共享整个数据目录，备份应使用非密钥导出。
  • 平台与调度：设置页按本机返回的平台信息展示系统调度名称（macOS 为 launchd，Windows 为任务计划程序）。启用需单独确认，Windows 任务需要当前用户已登录。Windows 适配未进行实机验收，不能把实现或 mock 验证当作 Windows 真机保证。
  • 不依赖 Agent：Bark / Webhook 由独立本机控制台直接请求接收服务。无需 DSH、Agent 或额外通知命令，旧本机命令仅为已有 macOS 用户兼容保留。通知测试不会请求模型，不会改旧任务；启用原生巡检仍可能消耗模型 API 配额。
  • HTTPS 默认开启：默认拒绝非 HTTPS。只有明确勾选风险开关才允许 HTTP；HTTP 会暴露凭据与内容，除已知风险的可信测试环境外不要使用。通知摘要会经接收服务处理，请自行评估服务方的隐私政策。
