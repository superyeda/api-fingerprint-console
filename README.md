# 检测大模型 API 是否降智

一个本机运行的小工具，专门用来回答一个问题：

> **我用的这个大模型 API，是不是变笨了？**

模型服务商可能悄悄把请求路由到更小的模型、量化版本或限流降级线路；中转站也可能"挂羊头卖狗肉"。单看一次回答很难判断，因为模型本来就有波动。

这个工具把这件事变成一个可以持续观察的指标：**用固定样本反复测同一条线路，看它的回答特征有没有发生变化。** 变了就提醒你复核，没变就继续安心用。

## 为什么需要它

- 你花高价买的是某个模型，实际返回的可能是另一个；
- 某条线路今天开始回答变短、变敷衍，但你分不清是网络问题还是模型换了；
- 你有多把 Key、多个中转，想知道是哪一条出了问题；
- 你不想每天手动复制问题去试，也不想靠"感觉"判断。

它不猜、不靠聊天记录，而是按计划自动取样、留存历史，让你在变化发生时有据可查。

## 它怎么判断"降智"

用一组固定的计数类问题向 API 取样，把回答的统计特征与参考库比对，得到这条线路当前最像哪一类模型。

- 结果与目标模型一致 → **指纹匹配**；
- 与目标模型不一致 → **疑似变化**，需要人工复核；
- 样本不足或置信度不够 → **暂不确定**；
- 请求失败、认证失败、超时 → **技术错误**。

需要说清楚：**指纹是观察信号，不是"智商测试"。** 它能提示"这条线路的回答特征变了"，但不能单独证明服务商一定换了模型，也不衡量模型能力高低。发现异常时，请结合账单、服务商公告和实际回答一起判断。

## 怎么用

### 1. 启动

优先从 [Releases](https://github.com/superyeda/api-fingerprint-console/releases) 下载完整安装包，解压到普通文件夹。

| 系统 | 启动 |
|---|---|
| macOS | 双击 `启动指纹巡检台.command` |
| Windows | 双击 `启动指纹巡检台.cmd` |

需要 Node.js 22+ 和 Python 3.7+。启动后浏览器打开 <http://127.0.0.1:47831>。

启动、保存配置、看历史都不会产生模型请求，只有你明确点"检测"才会。

### 2. 添加要观察的线路

在「巡检概览 → 添加接口」填写：

- 接口名称，例如"主力中转"；
- API Base URL；
- 请求模型；
- 接口协议（Responses / Chat Completions / Messages）；
- 期望参考类（你想确认它是哪个模型）；
- 保存。

然后在这个接口下添加 API Key，给每把 Key 起个能认出来的别名，例如 `main`、`backup`、`同事的 Key`。同一 URL 可以放多把 Key，分别观察。

### 3. 先只测一把 Key

第一次建议只测一把 Key，确认配置正确、能正常拿到结果，再扩大范围。

点击「检测这个 Key」前会提示可能产生费用，确认后才执行。每把 Key 一轮取 3 个样本。

### 4. 设置定时，让它自己盯着

在「调度与设置」选择间隔（1/2/3/4/6/8/12/24 小时）和分钟，明确确认后启用。

启用后，只要电脑开机、已登录、有网络，它就会按计划自动检测：

- 关闭网页不影响任务；
- 不会因为保存设置就立刻扣费；
- 同一时刻不会重复启动；
- 不需要云端服务器，也不依赖任何 Agent。

### 5. 出问题时收到通知

在「通知配置教程」页面按步骤配置 Bark 或 Webhook。保存后可以单独发一条测试通知，确认手机能收到。

检测出现异常时会推送摘要；手机没收到时，教程里有排错步骤。

## 适合谁

- 通过中转或代理使用大模型 API 的个人；
- 同时维护多条线路、多把 Key 的小团队；
- 想留下"某天开始变差"证据的人；
- 不想把 Key 交给第三方监控平台的人。

## 配置示例：DeepSeek

| 字段 | 填写 |
|---|---|
| Base URL | `https://api.deepseek.com/v1` |
| 协议 | Chat Completions |
| 请求模型 | `deepseek-flash` |
| 期望参考类 | `deepseek-v4.1-flash-1017` |

请求模型和期望参考类不是同一个字段：前者是发给服务商的名字，后者是你要对照的指纹类别。用其他服务时，向服务商确认这两项和协议即可。

## 费用与隐私

- 每把 Key 每轮 3 个样本，服务商会按 Token 计费；定时任务会持续产生请求，启用前先确认余额和单价；
- 保存配置、查看历史、发送通知测试都不调用模型；
- API Key 只保存在本机，不会上传到任何第三方；
- 工具只监听 `127.0.0.1`，页面和导出都不会回显 Key；
- 检测请求会发给你配置的模型服务商，通知摘要会发给你配置的 Bark/Webhook。

## 常见问题

**结果是"疑似变化"，是不是就一定降智了？**
不一定。它表示这条线路的回答特征与目标模型不一致，值得复核。请结合服务商公告、账单、实际回答判断。

**"技术错误"代表什么？**
代表这一轮没测成：可能是 Key 失效、余额不足、网络问题或服务端报错。技术错误不能当成降智结论。

**一定要一直开着电脑吗？**
定时任务运行在本机，需要电脑开机并登录。它不是云端 24 小时监控。

**支持哪些系统？**
macOS 和 Windows 都可以启动和设置定时。Windows 启动入口已做兼容修复，但完整流程仍建议先做单 Key 检查再开启付费定时。

## 从源码运行

```bash
git clone https://github.com/superyeda/api-fingerprint-console.git
cd api-fingerprint-console
npm ci --ignore-scripts
npm start
```

访问 <http://127.0.0.1:47831>。开发测试使用模拟服务，不会发送真实模型请求。
