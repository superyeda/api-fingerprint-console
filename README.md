# API 指纹巡检台

> 为需要长期观察模型接口的个人和小团队准备的本机巡检产品。
>
> 把多个 API 地址、多个 Key 和巡检计划放在一个地方，定时取得结果，发现异常时再人工复核。

## 它能解决什么问题？

当你同时使用多个模型服务、代理线路或 API Key 时，最容易遇到的是：

- 不知道某条线路什么时候开始表现异常；
- 不同 Key 的结果混在一起，很难比较；
- 想定时观察，却不想依赖云端监控或复杂的 Agent；
- 想收到通知，但又不想把 API Key 交给第三方平台；
- 换电脑、换模型后，原来的配置很难复用。

API 指纹巡检台把这些事情收进一个本机页面：**配置一次、按计划观察、留下历史、异常时通知你。**

它适合：

- 个人开发者观察自己的模型线路；
- 小团队比较多个供应商或中转线路；
- 对同一 URL 使用多把 Key，分别观察可用性和表现；
- 需要在 Mac 或 Windows 上运行的本机巡检任务。

## 主要功能

### 1. 一个页面管理多个 API

每个接口可以设置：

- 接口名称和 Base URL；
- 请求模型；
- Responses、Chat Completions 或 Messages 协议；
- 推理强度；
- 期望对照类别。

同一个接口可以添加多把 Key，并为每把 Key 设置自己的别名，例如 `main`、`backup`、`team-a`。Key 保存后不会在页面回显。

### 2. 用固定样本持续观察

每轮巡检会为每把启用的 Key 取得 3 个样本，再与参考库比较，形成：

- 指纹匹配；
- 疑似变化；
- 暂不确定；
- 技术错误。

历史结果按接口和 Key 分开保存，方便查看某一条线路的变化，而不是只看一个混合总数。

### 3. 可复用的定时任务

可以选择每 1、2、3、4、6、8、12 或 24 小时运行，并指定分钟数。

- 电脑开机、用户登录且有网络时运行；
- 关闭网页不影响已经启用的本机任务；
- 不会因为保存设置就立刻发起模型请求；
- 不会把旧任务自动改成新版本，升级时会要求明确确认；
- 同一轮不会重复启动，避免重复请求和重复计费。

### 4. 内置 Bark 和 Webhook 通知

在产品页面的 **「通知配置教程」** 中即可完成设置：

- Bark：适合接收 iPhone / iPad 通知；
- 通用 Webhook：适合自己的机器人、工作流或通知服务；
- Slack、企业微信群机器人、钉钉文本格式；
- 保存和发送测试分开，测试消息需要单独确认；
- 通知测试不会调用模型，也不会修改巡检历史。

### 5. 配置可迁移

导出文件只包含非密钥配置：接口、模型、别名、计划和通知偏好。不会导出 API Key、Bark 设备 Key 或 Webhook 密钥。

把导出文件带到另一台电脑后重新填写密钥，就可以复用原来的巡检结构。

## 最快开始

### 第一步：下载并启动

优先从 GitHub **Releases** 下载完整发布包。完整发布包包含运行所需依赖，解压到普通文件夹后启动：

| 系统 | 启动方式 |
|---|---|
| macOS | 双击 `启动指纹巡检台.command` |
| Windows | 双击 `启动指纹巡检台.cmd` |

首次启动需要：

- Node.js 22 或更高版本；
- Python 3.7 或更高版本；
- 本机可以访问你要检测的 API。

启动后打开 <http://127.0.0.1:47831>。启动、保存和页面浏览不会产生模型请求。

> Windows 请先完整解压 ZIP，不要在压缩包预览窗口里直接运行。若启动窗口出现提示，保留窗口内容即可排错；不要把 API Key 发给任何人。

### 第二步：添加一条接口

在 **「巡检概览 → 添加接口」** 中填写：

1. 接口名称；
2. API Base URL；
3. 请求模型；
4. 接口协议；
5. 期望参考类；
6. 保存。

然后在接口卡片中添加一把或多把 API Key，并为每把 Key 设置别名。

### 第三步：先只测试一把 Key

启用接口和目标 Key 后，选择 **「检测这个 Key」**。检测前产品会明确提醒可能产生费用。

建议第一次只测一把 Key：

1. 确认接口地址、模型名和协议；
2. 确认 Key 已保存且状态为可用；
3. 确认费用和账户余额；
4. 只检测一把 Key；
5. 在「检测历史」查看结果。

### 第四步：配置定时和通知

确认单次结果正常后，再到 **「调度与设置」**：

1. 选择巡检间隔和分钟；
2. 明确确认后启用系统定时；
3. 打开「通知通道」；
4. 按页面里的教程填写 Bark 或 Webhook；
5. 保存后，再单独发送一条测试通知。

## 常见服务配置示例

### DeepSeek 官方 API

| 字段 | 填写内容 |
|---|---|
| Base URL | `https://api.deepseek.com/v1` |
| 接口协议 | `Chat Completions` |
| 请求模型 | `deepseek-flash` |
| 期望参考类 | `deepseek-v4.1-flash-1017` |

`deepseek-flash` 是请求模型名称，期望参考类是用于比较的版本类别，两者不是同一个字段。其他兼容 OpenAI Chat Completions 的服务也可以按同样方式配置。

### 其他 OpenAI 兼容服务

通常需要向服务商确认四项内容：

- Base URL；
- 请求模型名；
- 使用的协议；
- 该模型对应的参考类别。

如果服务商只提供自定义协议，或返回格式与所选协议不兼容，结果会显示为技术错误，而不是模型变化结论。

## 如何理解结果

- **指纹匹配**：样本与选定参考类别一致；
- **疑似变化**：样本与目标类别不一致，需要人工复核；
- **暂不确定**：样本不足或置信度不足；
- **技术错误**：请求、认证、网络、参考库或服务响应没有完成。

指纹结果是一个观察信号，不是模型身份认证，也不是能力评分。技术错误不能当成模型降级；疑似变化也应该结合服务商公告、账单、响应内容和其他线路一起判断。

## 费用提醒

每把 Key 每轮默认取得 3 个样本，模型服务商可能按输入、输出和推理 Token 计费。定时任务会持续产生请求：启用前请先确认账户余额、限额和服务商价格。

保存配置、打开页面、导出非密钥配置、查看历史和发送通知测试不会调用模型。测试通知只会向你已经保存的通知通道发送一条真实消息。

## 数据和隐私

- 产品只监听本机地址 `127.0.0.1`；
- API Key 不通过页面 GET、普通导出或 URL 返回；
- macOS 使用本机文件权限保护数据；
- Windows 使用当前账户保护保存的密钥；
- 任何检测请求都会发送到你配置的模型服务商；
- 通知摘要会发送到你配置的 Bark 或 Webhook 服务；
- 不要分享实际数据目录、备份文件或完整 Webhook URL。

如果要迁移配置，请使用页面的非密钥导出，不要直接复制整个数据目录。


## 从源码运行

如果你是开发者，也可以直接克隆仓库：

```bash
git clone https://github.com/OWNER/REPO.git
cd api-fingerprint-console
npm ci --ignore-scripts
npm test
python3 -m unittest product_test.py
npm start
```

然后访问 <http://127.0.0.1:47831>。开发测试使用合成凭据和模拟服务，不会替你发送真实模型请求或通知。
